什么是提示注入攻击？举一个防御手段

## 最终回答
**结论：** 提示注入攻击是指攻击者通过精心构造输入来操纵大语言模型（LLM），使模型偏离原本意图、绕过规则或执行非预期操作，可能导致敏感数据泄露、权限提升甚至代码执行等问题[1][2][3][4]。OWASP 将其列为 LLM 应用的首要风险类别[1][10]。防御上可采用分层防御，例如用 Microsoft Prompt Shields 检测注入尝试，并配合加固系统提示、Spotlighting 隔离不可信输入等措施[10]。

**展开：**

- **定义与机制：** 提示注入漏洞发生在用户输入改变 LLM 行为或输出、使其产生非预期结果时；这些输入甚至不需要人类可读，只要能被模型解析即可[3]。攻击者可利用精心构造的输入让模型在不知情的情况下执行其意图[2]。
- **主要类型：** 直接提示注入又称“越狱”，攻击者直接覆盖或套取底层系统提示[2]；间接提示注入则来自网站、文件等外部内容，模型在读取这些内容时可能被其中的恶意指令影响[3][7][10]。
- **风险：** 证据指出，提示注入可导致数据外泄、社会工程、权限提升等后果[2][4]；OWASP 给出的示例中，直接注入甚至可能借助后端不安全函数导致远程代码执行[2]。
- **防御举例：** 一个具体手段是 **Spotlighting/隔离不可信输入**：微软将其列为预防性技术，用于把不可信输入与系统指令隔离开来[10]。同时，微软还使用 Prompt Shields 作为检测工具，并配合数据治理、用户同意流程和阻断已知数据外泄方式等缓解措施[10]。另一项证据显示，Semantic Kernel 默认将插入提示的内容视为不安全并进行编码，开发者需显式“选择加入”才能信任特定内容[6]。
- **限制：** 证据强调应使用纵深防御，而不是只依赖单一输入过滤或输出过滤；某层防御失效时，其他层仍可兜住损害[5][10]。因此，上述手段应视为多层防御的一部分，而非完全消除风险的单点方案。
